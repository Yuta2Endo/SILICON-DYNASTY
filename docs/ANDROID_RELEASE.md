# Android Release Specification

## Release identity

| Field | Value |
| --- | --- |
| App name | SILICON DYNASTY |
| Application ID | `com.silicondynasty.game` |
| Version | 1.0 (versionCode 1) |
| Minimum Android | API 24 (Android 7.0) |
| Target / compile SDK | API 36 |
| Web layer | React 19 + TypeScript + Vite 8 + Capacitor 8 |
| Orientation | Responsive, all supported orientations |

The Android project is generated by Capacitor and kept under `android/`.
Copied web assets, build outputs, local SDK paths and signing secrets are ignored.

## Prerequisites

- Node.js 22.12+ and npm.
- JDK 21 (verified with Java 21.0.13).
- Android SDK with platform 36, build-tools 36 and platform-tools.
- `ANDROID_HOME` or `ANDROID_SDK_ROOT` pointing at the SDK.
- For device testing: USB debugging enabled and an authorized `adb` device.

## Build

Run from the repository root in PowerShell:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
npm run build
npx cap sync android
Set-Location android
.\gradlew.bat assembleDebug --no-daemon
.\gradlew.bat bundleRelease assembleRelease --no-daemon
```

`npm run build` runs TypeScript checks and the production Vite build before
Capacitor copies `dist/` into the Android project.

### Artifacts

| Artifact | Path | Size |

| Debug APK | `android/app/build/outputs/apk/debug/app-debug.apk` | 4,379,008 bytes |

The release APK and AAB are unsigned. They are build outputs, not
publication-ready artifacts. `apksigner verify` reports `DOES NOT VERIFY`
because there is no signature, and `jarsigner` reports the AAB as unsigned.

## Signing

Never commit a keystore, passwords or `keystore.properties`. The Android
`.gitignore` excludes `*.jks`, `*.keystore` and `keystore.properties`.

Create an upload key outside the repository:

```powershell
keytool -genkeypair -v `
  -keystore "$env:USERPROFILE\silicon-dynasty-upload.jks" `
  -alias silicon-dynasty `
  -keyalg RSA -keysize 4096 -validity 10000
```

For local Gradle signing, create `android/keystore.properties` (ignored) and
add a release `signingConfig` in `android/app/build.gradle` that reads it.
Keep the keystore outside the repository and back it up securely.

For an already-built artifact, sign explicitly:

```powershell
$env:ANDROID_HOME = "$env:LOCALAPPDATA\Android\Sdk"
& "$env:ANDROID_HOME\build-tools\36.0.0\apksigner.bat" sign `
  --ks "$env:USERPROFILE\silicon-dynasty-upload.jks" `
  --out android\app\build\outputs\apk\release\app-release-signed.apk `
  android\app\build\outputs\apk\release\app-release-unsigned.apk
```

For Google Play, prefer Play App Signing with a separate upload key. The
release gate is not satisfied until the signed artifact is verified with
`apksigner verify --verbose` or uploaded to the Play Console.

## Versioning

Update both fields in `android/app/build.gradle` for every published build:

```gradle
versionCode 1
versionName "1.0"
```

`versionCode` must increase monotonically. Keep the web package version and
release notes in sync.

## Install and launch

With one authorized device:

```powershell
$adb = "$env:LOCALAPPDATA\Android\Sdk\platform-tools\adb.exe"
& $adb devices -l
& $adb install -r android\app\build\outputs\apk\debug\app-debug.apk
& $adb shell am start -n com.silicondynasty.game/.MainActivity
```

For release testing, sign the APK first and install the signed file. Use
`adb logcat` to inspect WebView or native errors.

## Saves and lifecycle

- The game autosaves after every successful command.
- IndexedDB is the primary store; localStorage is the fallback.
- Manual slots, backup, JSON import/export and recovery are available in
  Settings.
- A normal reload, app restart or process recreation loads the latest autosave.
- Android WebView storage survives background/resume and normal restarts.
- Clearing app data or uninstalling the app deletes local saves. There is no
  cloud sync.
- Drafts that have not been saved are intentionally not persisted; the app
  warns before discarding them.

Production-web QA verified that a day advanced to 1995-01-02 survived a reload,
a tab close and a new tab, with no console errors. Android background/resume and
process-death behavior still require verification on a device.

## Performance and memory

Production web build:

- Production build is code-split: main entry 364.94 kB (99.26 kB gzip),
  React vendor 218.77 kB (68.25 kB gzip), CSS 121.57 kB (22.86 kB gzip).
- Feature screens are lazy-loaded; the production build has no Vite chunk-size
  warning.
- Lighthouse on the production preview: accessibility 100, best practices 100,
  SEO 100.
- Desktop reload trace: 715 events, one long task of 60.35 ms, JavaScript parse
  18.56 ms, layout 2.43 ms.
- Desktop heap after load: 6.9 MB used / 13.5 MB total, 268 DOM nodes.
- Vite chunk-size warning: none in the current split production build.

Android startup time, frame pacing, heap growth, battery use, thermal behavior
and long-session memory were **not measured** on the vivo I2405 used for the
install/lifecycle check. Do not treat desktop numbers as Android profiling.

## Known limitations

- The debug APK passed real-device install/launch and save-lifecycle checks;
  the signed release artifact has not yet been installed and verified.
- Release APK/AAB are unsigned until a private upload key is configured.
- No Android Studio/device profiler data, native crash reporting or Play
  Console internal testing was performed.
- The app icon and splash screen still use Capacitor defaults; store branding
  is a separate release-polish task.
- No end-to-end test script exists; `test:e2e` is NOT AVAILABLE.
- There is no cloud save sync; local data is lost if app storage is cleared.
